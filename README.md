## 亚马逊评论为什么这么难抓

亚马逊的反爬机制在电商平台里算顶级的。几个核心难点：

**IP 封禁极快。** 同一个 IP 连续请求评论页面，通常几十次就会触发验证码或直接 403。普通住宅代理扛不住高频请求。

**页面结构动态变化。** 亚马逊会对不同地区、不同登录状态的用户返回不同的 HTML 结构，写死的 XPath 选择器隔几周就可能失效。

**评论分页与异步加载。** 部分评论通过 AJAX 动态加载，单纯请求静态 HTML 拿不到完整数据。

自己维护代理池 + 解析器的成本其实很高。代理费、维护时间、封号后的调试，算下来不如直接用现成的 API 服务划算——前提是价格合理。

## ScraperAPI 是什么、怎么解决这些问题

ScraperAPI 本质上是一个代理 + 渲染 + 反爬的中间层。你把目标 URL 丢给它的 API 端点，它帮你处理 IP 轮换、浏览器指纹、验证码识别、JavaScript 渲染，然后把干净的 HTML 返回给你。

对于亚马逊评论抓取，它有一个专门的 Amazon 结构化数据端点。你传入 ASIN，它直接返回 JSON 格式的评论数据——评分、标题、正文、日期、是否 Verified Purchase，全都解析好了。省掉了自己写解析器的活。

我实际跑下来，亚马逊评论页面的请求成功率能稳定在 95% 以上。偶尔有失败的，重试一次基本就过了。对比之前自己搞免费代理那种三成功率，体验差距很大。
